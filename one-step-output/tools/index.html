站点规划

站在访客视角的功能区设计提案（不改动现有样式）

「除了死亡，每一天都是婚礼」— 你的站子已经有一套很有个人气质的语言：八音盒、调色盘、小纸条。规划沿用这套语言。

一、现状盘点

当前导航：首页 / Note / Moments(发疯日常) / 八音盒(音乐) / 调色盘(相册) / 小纸条(信条墙) / 关于我。
问题：① 「Note」是英文而其他是中文意象名，风格断裂；② 笔记(DL-cards)、博客文章、小纸条、动态四类内容的入口分散且层级不清；③ links/flinks 双空页残留；④ 新访客不知道「小纸条」和「Moments」区别是什么。

二、访客旅程设计

首屏 · 是谁→ 日常 · 在生活→ 思考 · 在学什么→ 收藏 · 审美沉淀→ 连接 · 找到我

三、建议导航（两级）

一级栏目意象命名内容理由
首页花间精选文章 + 最新动态卡片流一屏建立人格印象
随笔拾光博客文章（含技术文）按分类聚合统一中文名，替代 Note
日常发疯现场Moments 动态流（保留现名亦可）高频轻内容，访客最常刷
手账小纸条信条墙（说说）并入或紧邻日常两者都是碎片表达，相邻降低理解成本
相册调色盘摄影/画廊保留，已是很好的名字
声音八音盒音乐页保留
关于花主自述自我介绍 + 更新日志 + 友链合并于此友链空页不再独立存在

四、落地步骤（全部可在本系统完成）

① 「页面」里改 about/index.md 加入更新日志与友链 → 删除 flinks/
② themes/butterfly/_config.yml 的 menu 改为上表（此步需改主题配置文件，属一次性变更）
③ 首页 index.md 加一段欢迎语 + 指向各区的卡片链接
④ 数据源统一：小纸条以 shuoshuo.json 为准，废弃 shuoshuo.yml 与 _data/shuoshuo.yml（本系统只读写 json，天然一致）

五、视觉红线

樱花飘落、游鱼 footer、波浪 hero 这些是你站的灵魂装饰，重构时一律保留；本管理系统采用樱吹雪配色正是为了「后台与前台同源」——管理时看到的粉调，就是访客看到的粉调。
